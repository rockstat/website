Задача раздела — получить идентификаторы посетителя в сторонних сервисах, чтобы потом связывать
данные сервер-сервер. В текущей версии Web-SDK это делается двумя способами.

## Автоматическая синхронизация с GA4 и Яндекс Метрикой

Если на странице подключены Google Analytics 4 или Яндекс Метрика, SDK сам получает их client id,
отправляет внутреннее событие `user_params` и сохраняет значения в хранилище. Далее они приходят
в блоке `user` каждого сообщения:

```json
"user": {
  "ga4ClientId": "2039255293.1537236640",
  "ymId": "1537242943246737376"
}
```

Ничего настраивать не нужно. Чтобы синхронизация успела, сниппет Rockstat лучше ставить выше
счётчиков GA4 и Метрики.

## Идентификаторы из своего кода

Любой идентификатор, который вы получаете на стороне сайта, передаётся через `identify` и
попадает в блок `user` всех последующих сообщений:

```javascript
rstat4('identify', { hybridPid: 'xxxxxxxxx' });
```

Подробнее в [JavaScript API](/docs/reference/web-sdk/js-api#identify--идентификация-пользователя).

## Параметр pixelSync

<Alert>
  Параметр `pixelSync` и перехват адресов загружаемых пикселей зарезервированы и в версии 5.x не
  работают. Конфигурация ниже описывает задуманное поведение и приведена для совместимости
  с прошлыми версиями документации.
</Alert>

Идея: SDK смотрит адреса загружаемых на странице пикселей, по регулярному выражению вытаскивает
из них идентификатор и сохраняет его в указанный параметр пользователя.

```javascript
pixelSync: {
  patterns: [
    ['https://dss-us\\.hybrid\\.ai/Pixel/Track2.*pid=([0-9a-z]+)', 'hybridPid']
  ]
}
```

Результат был бы равнозначен вызову `rstat4('identify', { hybridPid: '...' })`.
